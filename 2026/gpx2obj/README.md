# Треки → OBJ: `gpx2obj.py` и `fuse_track.py`

Два скрипта на чистом Python 3 (только стандартная библиотека, venv не нужен):

| Скрипт | Вход | Выход |
|---|---|---|
| `gpx2obj.py` | GPX-трек | OBJ: точки центра дороги или непрерывный меш дороги |
| `fuse_track.py` | папка трека с `gnss-nav.csv` и `imu.csv` | сшитый трек: OBJ с точками и GPX для `gpx2obj.py` |

Типичный конвейер: `fuse_track.py` убирает скачки GNSS, `gpx2obj.py` строит по результату меш.

```
папка трека ──fuse_track.py──▶ <трек>-fused.gpx ──gpx2obj.py --mode road──▶ <трек>-fused-road35.obj
```

## Система координат

Общая для обоих скриптов, задаётся в `gpx2obj.py`:

- Центр `LAT0, LON0` (44.695970867268315, 20.501830006042887) переходит в начало координат.
- Земля плоская: метров на градус широты и долготы считается один раз по широте центра, дальше линейно.
- Высота абсолютная (из GPX/CSV), опция `--ele-offset` вычитает константу.
- Оси OBJ по умолчанию: X = восток, Y = вверх, Z = юг (правая тройка, Y-up). С `--z-up`: X = восток, Y = север, Z = вверх.

В шапке каждого OBJ (комментарии `#`) записаны центр, оси и параметры генерации.

## `gpx2obj.py`

```
python3 gpx2obj.py --mode {waypoints,road} [опции] файл.gpx [файл2.gpx ...]
```

Читает все `trkpt` из GPX (широта, долгота, высота). Выходной файл кладётся рядом с
входным (или в `-o каталог`), имя: `<имя_gpx>-waypoints.obj` или `<имя_gpx>-road35.obj`
(число в суффиксе это ширина дороги ×10).

### Режим `waypoints`: точки центра дороги

Каждая точка трека становится вершиной `v` плюс элемент `p`. Все точки сохраняются как есть.

```bash
python3 gpx2obj.py --mode waypoints track.gpx              # track-waypoints.obj
python3 gpx2obj.py --mode waypoints --polyline track.gpx   # плюс ломаная `l` через все точки
python3 gpx2obj.py --mode waypoints --min-step 0.5 *.gpx   # выкинуть точки ближе 0.5 м к предыдущей
```

### Режим `road`: непрерывный меш дороги

Лента с общими вершинами, один четырёхугольник на метр пути, нормали вверх.
Ширина 3.5 м на прямых, в крутых поворотах плавно растёт до 5 м (уширение проезжей
части в кривых), машина считается едущей по центру.

```bash
python3 gpx2obj.py --mode road track.gpx                         # track-road35.obj
python3 gpx2obj.py --mode road --width 3.0 --width-max 4.5 *.gpx # другие ширины (суффикс станет road30)
python3 gpx2obj.py --mode road --rects track.gpx                 # старый вариант: независимые прямоугольники
python3 gpx2obj.py --mode road --z-up -o obj/ *.gpx              # Z вверх, всё в папку obj/
```

Что происходит с треком перед построением (по порядку):

1. **Дедупликация**: подряд идущие точки ближе `--min-step` (0.2 м) выкидываются.
2. **Дрейф высоты** (`flatten_z_drift`): если высота уходит от опорной точки быстрее,
   чем позволяет уклон 15% плюс `--jump-z` (2.5 м), участок прижимается к опорной высоте.
   Короткий глитч (высота вернулась) исчезает целиком, длинный превращается в одну ступеньку.
3. **Разрывы GNSS** (`detect_jumps`/`fix_jumps`): отрезок, не укладывающийся в гипотезу
   «машина ехала по дуге», считается скачком. Догоняющие скачки вдоль дороги (после
   заморозки приёмника) скачком не считаются. Пара противоположных скачков ближе
   `--glitch` (60 м) вырезается. Остальные плавно сшиваются: невязка размазывается назад
   на `--jump-blend` (40 м) в плане и `--jump-blend-z` (100 м) по высоте.
4. **Пересэмплирование** с шагом `--step` (1 м) и сглаживание скользящим средним:
   `--smooth` (6 м) в плане, `--smooth-z` (20 м) по высоте.
5. **Кривизна** по трём точкам с плечом `--curv-span` (12 м). Ширина линейна по кривизне:
   `--width` при радиусе ≥ `--r-narrow` (120 м), `--width-max` при радиусе ≤ `--r-wide` (20 м),
   затем сглаживание ширины на `--width-smooth` (25 м), это длина отгона уширения.
6. **Лента**: смещение кромок по биссектрисе (miter, ограничение 2×), на внутренней стороне
   поворота смещение не больше 0.9 локального радиуса, чтобы кромка не выворачивалась.

В конце печатается строка статистики: число квадов, диапазон ширины, минимальный радиус,
сколько метров уширено, сколько скачков сшито, точек глитчей вырезано, точек дрейфа
высоты исправлено, вершин зажато на внутренней кромке.

```
track.gpx -> track-road35.obj  (3939 quads, width 3.50..5.00 m, min R 11 m, widened 1841 of 3940 m,
                                 jumps blended 4, glitch pts cut 0, z-drift pts 0, inner clamps 5)
```

Если `jumps blended` и `z-drift pts` большие, трек лучше сначала прогнать через `fuse_track.py`.

### Опции `gpx2obj.py`

| Опция | Default | Смысл |
|---|---|---|
| `--mode` | обязательна | `waypoints` или `road` |
| `--lat0`, `--lon0` | центр Авалы | центр координат |
| `--ele-offset` | 0 | вычесть из высоты |
| `--z-up` | | оси X=восток Y=север Z=вверх |
| `-o DIR` | рядом с gpx | каталог для OBJ |
| `--min-step` | 0 / 0.2 | дедупликация (waypoints / road) |
| `--polyline` | | waypoints: добавить ломаную `l` |
| `--width`, `--width-max` | 3.5, 5.0 | ширина на прямой и в самом крутом повороте, м |
| `--r-narrow`, `--r-wide` | 120, 20 | радиусы, между которыми идёт уширение, м |
| `--width-smooth` | 25 | длина отгона уширения, м |
| `--step`, `--smooth`, `--smooth-z` | 1, 6, 20 | шаг и окна сглаживания, м |
| `--curv-span` | 12 | плечо оценки радиуса, м |
| `--jump`, `--jump-z` | 3.0, 2.5 | пороги скачка в плане и по высоте, м |
| `--jump-blend`, `--jump-blend-z` | 40, 100 | длина сшивки скачка, м |
| `--glitch` | 60 | макс. длина вырезаемого глитча, м |
| `--rects` | | независимые прямоугольники вместо ленты |

## `fuse_track.py`

```
python3 fuse_track.py [опции] папка_трека [папка2 ...]
```

Восстанавливает трек по `gnss-nav.csv` и `imu.csv` из папки трека. На выходе рядом с
папкой (или в `-o`):

- `<папка>-fused.obj`: точки трека (~10 Гц) в той же системе координат, что у `gpx2obj.py`;
- `<папка>-fused.gpx`: тот же трек с временем и высотой, вход для `gpx2obj.py --mode road`.

```bash
python3 fuse_track.py 2026-09-05T14-50-22-193Z
python3 fuse_track.py 2026-09-05T1[45]-*Z/                 # все треки сразу
python3 fuse_track.py --every 5 -o fused/ 2026-09-05T1*Z/  # каждая 5-я точка (~2 Гц), в папку fused/
python3 gpx2obj.py --mode road *-fused.gpx                 # меш по сшитым трекам
```

### Как работает

Расширенный фильтр Калмана с состоянием
`[восток, север, курс, скорость, смещение гироскопа, высота, уклон]`
и сглаживатель Рауха–Тунга–Штрибеля (обратный проход по записи, поэтому переходы
через скачки симметричные, без запаздывания).

- **Предсказание** на каждом сэмпле IMU: курс интегрируется по gyroZ (рад/с, знак
  `GYRO_SCALE = -1`), позиция по скорости и курсу, высота по скорости и уклону
  (на стоянке высота меняться не может).
- **Коррекция** на каждой реальной эпохе GNSS (~1 Гц; 10 Гц в логе это интерполяция
  приёмника, такие сэмплы пропускаются, `--all-nav` включает их обратно):
  позиция с дисперсией из `hAccuracy`, доплеровская скорость из `speedAccuracy`,
  курс (только быстрее `--hdg-min-speed` и точнее `--hdg-max-acc`), высота из `vAccuracy`.
- **Робастность**: если невязка не проходит порог χ², дисперсия измерения раздувается
  по Хуберу. Скачок решения GNSS (переход RTK none → float) не отбрасывается, но фильтр
  подтягивается к нему плавно.
- Эпохи с `fixType` ≠ `3D-Fix` (внутреннее счисление приёмника, «No Fix») пропускаются:
  там приёмник держит позицию и пишет скорость 0.
- Акселерометр не используется: в этих логах он с изменением скорости не коррелирует.

Статистика в конце:

```
2026-09-05T14-50-22-193Z -> ...-fused.obj, ...-fused.gpx
   nav epochs 564, imu 4051, points 4615; pos updates downweighted 80/564, hdg 58/440, h 131/564
   max step 1.63 m; deviation from raw GNSS: median 0.36, p95 4.78, max 9.90 m
```

`downweighted` это сколько измерений получили пониженный вес (норма 5–15%, в основном
на скачках). `deviation from raw GNSS` показывает, насколько сшитый трек ушёл от сырых
позиций: медиана должна быть в пределах заявленной точности, максимум приходится на скачки.

### Опции `fuse_track.py`

| Опция | Default | Смысл |
|---|---|---|
| `--lat0`, `--lon0`, `--z-up`, `-o` | как в gpx2obj | координаты и вывод |
| `--every N` | 1 | выводить каждую N-ю точку |
| `--all-nav` | | использовать все 10 Гц сэмплы GNSS |
| `--q-pos` | 0.3 м/с | ошибка модели движения (снос) |
| `--q-gyro` | 0.03 рад/с | шум гироскопа |
| `--q-acc` | 0.8 м/с² | случайное ускорение (насколько быстро может меняться скорость) |
| `--q-bias` | 2e-4 рад/с/с | дрейф смещения гироскопа |
| `--q-h` | 0.05 м/с | ошибка модели высоты |
| `--q-grade` | 0.005 1/с | скорость изменения уклона |
| `--k-pos`, `--k-speed`, `--k-hdg`, `--k-h` | 1.0 | множители заявленных точностей GNSS |
| `--hdg-min-speed` | 2 м/с | курс GNSS берём только быстрее |
| `--hdg-max-acc` | 15° | курс GNSS берём только точнее |

Подсказки по настройке:

- Трек «срезает» повороты или дрожит: уменьшить `--q-pos`, увеличить `--k-pos`.
- Трек слишком послушно повторяет скачки GNSS: увеличить `--k-pos` (2–3), это ослабит доверие к позициям.
- Трек отстаёт после долгой заморозки GNSS: увеличить `--q-acc`.
- Высота ступеньками: уменьшить `--q-grade`, ступенька растянется на большее расстояние.

## Пример полного прогона

```bash
cd logs
python3 fuse_track.py 2026-09-05T1[45]-*Z/          # 5 треков -> *-fused.gpx, *-fused.obj
python3 gpx2obj.py --mode road *-fused.gpx          # *-fused-road35.obj
python3 gpx2obj.py --mode waypoints *.gpx           # сырые точки для сравнения
```

Полученные OBJ открываются в Blender через File → Import → Wavefront (.obj).
Так как оси уже Y-up, при импорте лучше оставить Forward = -Z, Up = Y; вариант с
`--z-up` импортировать с Forward = Y, Up = Z. Единицы метры, масштаб 1.
